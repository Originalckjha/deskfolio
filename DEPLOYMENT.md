# Deploying DeskFolio (Render + MongoDB Atlas, both free)

DeskFolio deploys as **one Render web service**: the Express API also serves the built React app,
so the whole site is on one URL like `https://deskfolio.onrender.com`. The database is a free
**MongoDB Atlas** cluster. No other services are needed.

Order: **Atlas first** (you need its connection string), then **Render**.

---

## 1. MongoDB Atlas

1. **Cluster:** a free **M0** cluster at <https://cloud.mongodb.com>. If you're creating one, pick a region
   near Render's `singapore` (AWS `ap-southeast-1` or `ap-south-1` Mumbai).
2. **Database user:** *Database Access* → your user → **Edit** → **Edit Password** → *Autogenerate Secure
   Password*. Copy it somewhere safe. (Reset it if it was ever pasted anywhere public or into a chat.)
3. **Network access:** *Network Access* → **Add IP Address** → **Allow access from anywhere** (`0.0.0.0/0`) → Confirm.
   Render's free tier has no fixed IP address, so Atlas must accept any address; the username and password
   still protect the database.
4. **Connection string:** take the string from *Connect → Drivers*, put your password in place of
   `<db_password>`, and add `deskfolio` before the `?`:

   ```
   mongodb+srv://<user>:<password>@<cluster>.mongodb.net/deskfolio?retryWrites=true&w=majority
   ```

   This is your `MONGODB_URI`. Autogenerated Atlas passwords are safe to paste as-is; if yours contains
   `@ : / ? # %`, URL-encode it first.

You don't create collections or indexes by hand: every Render build runs `npm run db:indexes`, which creates
them (safe to repeat).

## 2. Render

The repo has a [`render.yaml`](render.yaml) Blueprint that describes the whole service.

1. Sign in at <https://dashboard.render.com> (signing in with GitHub is easiest).
2. **New → Blueprint** → connect GitHub if asked → pick **deskfolio**.
3. Render reads `render.yaml` and shows one service, **deskfolio**. It asks for one value:

   | Variable | Value |
   | --- | --- |
   | `MONGODB_URI` | the Atlas string from step 1.4 |

   Everything else is preset. `JWT_SECRET` is generated by Render; `PORT` is set by Render.
4. Click **Apply** / **Deploy Blueprint**. The first build takes a few minutes. It:
   installs and builds the React app → installs the API → creates the database indexes → starts the server.
5. When it shows **Live**, open the service URL (top of the service page).
   `https://<your-service>.onrender.com/api/health` should return `{"status":"ok","db":"up",...}`.

If the build fails at `db:indexes`, Render can't reach Atlas: check the Network Access entry (step 1.3) and
the password in `MONGODB_URI`.

### Free-tier behaviour

- The service **sleeps after about 15 minutes** without visits. The next visit takes 30–60 seconds while it
  wakes; after that it's fast. A free uptime pinger hitting `/api/health` every 10 minutes keeps it awake.
- Every push to `main` on GitHub redeploys automatically.

### File uploads (optional, later)

Notes and links work straight away. For PDF/PPT/image uploads, create a free <https://cloudinary.com>
account and add these in Render → your service → **Environment**:
`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`. Render redeploys after you save.

## 3. After the first deploy

- [ ] `/api/health` returns `ok` / `db: up`
- [ ] The site loads the landing page and leaderboard
- [ ] Register an educator, create a space, add a note
- [ ] In a private window, register a student, join with the space's code, open the note, rate the educator
- [ ] The rating shows on the leaderboard

## Alternative: frontend on Vercel

[`client/vercel.json`](client/vercel.json) is still in the repo if you ever want the frontend on Vercel's CDN
instead: deploy `client/` to Vercel with `VITE_API_URL=https://<render-service>.onrender.com/api/v1`, and add
the Vercel URL to `CLIENT_ORIGINS` on Render.
